LOCK STATE MACHINE

Observed states
- READ_ONLY
- ACQUIRING_LOCK
- EDIT_LOCKED
- LOCK_LOST
- FORCED_READ_ONLY
- IDLE_TIMEOUT_GRACE

Observed operations
- acquire
- heartbeat
- status
- release
- takeover via canonical ForceTakeover flag

Canonical payloads
- LockAcquire(DB_KEY, SessionGuid, TabSessionId, ForceTakeover)
- LockHeartbeat(DB_KEY, SessionGuid)
- LockRelease(DB_KEY, SessionGuid)

Expected flow
1. integration-origin confirm when required
2. permission check
3. cache freshness validation
4. lock acquire
5. enter edit mode
6. heartbeat and status polling while edit lock is active
7. release on save/close/navigation where applicable
8. page-leave release is best-effort only and must stay session-aware

Forbidden behaviors
- blind unlock without session token
- parallel canonical takeover flags
- direct promotion of page-leave release into guaranteed save-on-unload semantics
