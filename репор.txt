Сессия 4 — Итог: 5 багов в gateway_canonical_api.py
БАГ 5 — MEDIUM: ReportExport — отсутствует поле ItemType
Сущность ExportRow в metadata имеет составной ключ (RootKey, ItemType, Num). Endpoint возвращал строки без поля ItemType — SAP UI5 не мог правильно идентифицировать записи. Также Num для пустых чеклистов был null вместо 0. Исправлено: добавлены ItemType: "CHECK"/"BARRIER"/"ROOT", правильный Num: 0, поля LpcText/ProfessionText, поддержка одиночного RootKey в payload.
БАГ 6 — КРИТИЧНЫЙ: SetChecklistStatus не читал URL query params
SAP UI5 callFunction с method: POST отправляет параметры как URL query string, но endpoint принимал только payload: dict (JSON body) — параметры всегда были пустыми, статус никогда не менялся. Исправлено: endpoint переписан как async, теперь читает параметры из query string с фоллбэком на JSON body.
БАГ 7 — MEDIUM: Дублирующаяся функция _to_current_user
Первое определение на строке 740 использовало "view" in permissions (старый строковый формат), второе (строка 779) — правильное, с "01" in permission_codes. Python использует последнее, но дубль вводил в заблуждение. Первое определение удалено.
БАГ 8 — MEDIUM: Mojibake в _current_user_summary
Строки с кириллицей в словаре permission_labels и возвращаемые строки функции были дважды закодированы (UTF-8 → Latin-1 → UTF-8). Поле SummaryText отображало бессмыслицу. Исправлено 5 строк бинарным патчем.
