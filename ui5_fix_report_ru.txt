UI5 / SAP-friendly cleanup and fix report

Что исправлено в этой итерации
1. Analytics year handling
- Устранена дублирующаяся и небезопасная логика парсинга года.
- Добавлен общий helper app/service/shared/YearValue.js.
- Контроллерный слой, runtime-слой и domain use case теперь используют единый safe parse path без silent fallback в 0.
- Добавлен app/service/contracts/AnalyticsUiContracts.js для путей view model и причин загрузки.

2. Analytics / XML cleanup
- Упрощена Analytics.view.xml:
  - форматирование refresh status теперь идёт от целого объекта refreshState;
  - убран громоздкий parts-binding с 8 частями;
  - source chip переведён на formatter.
- Приведены в читаемый вид тяжёлые XML-фрагменты:
  - app/views/Analytics.view.xml
  - app/views/fragment/DetailAttachmentsBody.fragment.xml
  - app/views/fragment/DetailControlActionRow.fragment.xml
  - app/views/fragment/DetailControlStatusRow.fragment.xml
  - app/views/fragment/WorkflowAnalyticsDeepBreakdowns.fragment.xml

3. Detail attachment hint hardening
- Убрана зависимость formatAttachmentUploadHint от полного controller instance.
- AttachmentUploadCore теперь принимает ResourceBundle, а не whole controller.
- Вынесены attachment-related raw strings в DetailRuntimeContracts.
- Удалён мёртвый и повреждённый mojibake fallback text path.

4. Theme / shell normalization
- ThemeContracts расширен константами для appView paths и sync sources.
- ThemeMixin переведён на ThemeContracts constants.
- AppShellCoordinator очищен от misleading dark-mode derived semantics.
- Сохранил безопасный morning-only режим без возврата рискованного dark path.

5. Lazy dialog / duplicate ID hardening
- LazyDialogRuntime больше не использует getView().getId() как fragment id.
- Теперь используется createId(resolveDialogId(...)), что снижает риск duplicate ID при повторных открытиях / FLP lifecycle.
- Analytics year picker тоже переведён на createId("analyticsYearPicker").

6. Tooling / guardrails
- Добавлены:
  - package.json
  - ui5.yaml
  - .editorconfig
  - .stylelintrc.json
- Добавлен минимальный standard UI5 build/preload path и CSS lint path.

Что нормализовано архитектурно
- Повторяющаяся year parsing logic сведена к одному helper.
- Повторяющиеся analytics view-model paths вынесены в AnalyticsUiContracts.
- Повторяющиеся attachment text keys / paths вынесены в DetailRuntimeContracts.
- Theme/shell magic strings частично вынесены в ThemeContracts.

Что осталось вне этой итерации
1. Полная глобальная вычистка raw strings по всем 400+ JS-файлам не завершена.
2. Полная дедупликация всех proxy/runtime слоёв по всему проекту не завершена.
3. Не выполнялся большой risky rewrite routing/FCL и всей service/framework структуры.
4. Не запускалась полноценная UI5 build/test pipeline в этом окружении — добавлен конфиг и path, но фактический build надо прогнать у вас локально/в CI.

Рекомендуемая следующая итерация
- глобальная инвентаризация raw strings по app/service/** и перевод в contracts/constants пакетами по доменам;
- выжигание pass-through runtime/proxy слоёв вокруг analytics/search/detail;
- единая схема ViewPathContracts для controller/view state путей;
- повторный static audit CSS/XML после прогонки stylelint и ui5 build.
