ATTACHMENT ARCHIVELINK CONTRACT

Target source of truth
- AttachmentSet is a metadata contract, not the canonical binary source.
- Frontend should use attachment metadata to decide open/download behavior.

Required metadata fields
- AttachmentKey: stable attachment identifier.
- FileName: display/download filename.
- MimeType: content type.
- FileSizeContent: display size / validation support.
- DownloadUrl: preferred productive download target when backend exposes stream endpoint.
- DocumentHandle: ArchiveLink/backend document handle for indirection.

Compatibility field
- Value remains present only as a legacy compatibility fallback for non-finalized local/mock flows.
- Value must not be treated as the long-term productive contract or cache source of truth.

Frontend rules
- Detail open must not preload attachments into the base snapshot.
- Attachment load is explicit/lazy.
- Attachment delete is local-only for unsaved rows and aggregate-save driven for persisted rows.
- Attachments stay outside the main detail cache snapshot and are synchronized separately.

Backend/Gateway rules
- Productive binary retrieval should resolve from DownloadUrl or backend stream indirection using DocumentHandle.
- ArchiveLink-compatible implementations must keep metadata stable even if the binary source implementation changes.
