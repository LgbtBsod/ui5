UPDATED LOCK STATE MACHINE

Observed states
- READ_ONLY
- ACQUIRING_LOCK
- EDIT_LOCKED
- LOCK_LOST
- FORCED_READ_ONLY
- IDLE_TIMEOUT_GRACE

Observed operations
- acquire
- heartbeat
- status
- release
- takeover via canonical ForceTakeover flag

Canonical payloads
- LockAcquire(ObjectUuid, SessionGuid, TabSessionId, ForceTakeover)
- LockHeartbeat(ObjectUuid, SessionGuid)
- LockRelease(ObjectUuid, SessionGuid)

Expected flow
1. permission check
2. lock acquire
3. cache freshness validation
4. enter edit mode
5. heartbeat and status polling while edit lock is active
6. release on save/close/navigation where applicable
7. page-leave release is best-effort only and must stay session-aware

Forbidden behaviors
- blind unlock without session token
- parallel canonical takeover flags
- direct promotion of page-leave release into guaranteed save-on-unload semantics
- lock acquire before integration-origin user confirm
