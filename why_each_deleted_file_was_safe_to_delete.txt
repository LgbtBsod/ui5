WHY EACH DELETED FILE WAS SAFE TO DELETE

app/service/domain/detail/DetailService.js
- Was a controller-bound pass-through wrapper around the same detail use cases already exposed by DetailFacade.
- Added only context construction aliases and duplicate method names, but no independent domain invariants.
- Controller now instantiates DetailFacade directly, so the wrapper no longer had a unique owner responsibility.

app/service/domain/detail/DetailUseCaseRegistry.js
- Only instantiated a static map of use case factories and returned it unchanged.
- The map is now built inside DetailFacade, which is the canonical public detail-domain entrypoint.
- Deleting it removed one non-semantic layer without changing business behavior.

app/service/domain/detail/DetailEntryAdapterRuntime.js
- Only executed use cases and delegated enter-edit/discard decoration to DetailWorkflowRuntime.
- Those helpers now live directly in DetailFacade, which already owned the public detail-domain API.
- The file had no transport boundary and no state ownership, so it was safe overengineering to remove.
